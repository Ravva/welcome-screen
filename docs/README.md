# Welcome Screen — архитектурный обзор

Этот файл является источником архитектурной правды для проекта `Welcome Screen`.

## Назначение

`Welcome Screen` — локальная система распознавания лиц на входе в здание. Система получает RTSP-поток с одной IP-камеры, распознаёт сотрудника или неизвестного посетителя, логирует событие и выводит приветствие на ТВ-экран через WebSocket.

Основной детальный документ требований: [`../PRD.md`](../PRD.md).

## MVP Scope

- Одна IP-камера в зоне узкого прохода/рамки металлоискателя.
- Один ТВ-экран для режима ожидания и приветствий.
- Локальный Docker-контур на Ubuntu Server.
- Распознавание через CompreFace на CPU.
- Stream Handler для RTSP, ROI и сэмплирования кадров.
- Backend API как центральный координатор бизнес-логики.
- PostgreSQL для сотрудников, настроек, пользователей и логов.
- Admin frontend для управления сотрудниками, фото, логами и настройками.
- TV frontend для отображения приветствий.
- Nginx как reverse proxy для HTTPS/WSS с самоподписанными сертификатами.
- Простая диагностика через `/health`.

## Компоненты

1. `camera-stream-handler` — получает RTSP-поток, применяет ROI, сэмплирует кадры и передаёт изображения на распознавание.
2. `compreface` — выполняет детекцию и идентификацию лиц.
3. `backend-api` — хранит бизнес-данные, управляет сотрудниками, применяет anti-flood, записывает события и рассылает WebSocket-уведомления.
4. `postgres` — хранит профили сотрудников, настройки, пользователей и логи посещений.
5. `tv-frontend` — отображает режим ожидания и карточки приветствия.
6. `admin-frontend` — предоставляет интерфейс управления сотрудниками и журналом посещений.
7. `reverse-proxy` — обеспечивает HTTPS/WSS и маршрутизацию через Nginx.

## Основной поток обработки

```text
IP Camera → Stream Handler → CompreFace → Backend → WebSocket → TV Frontend
```

Альтернативный поток допускается после тестирования задержек:

```text
IP Camera → Stream Handler → Backend → CompreFace → Backend → WebSocket → TV Frontend
```

## Ключевые ограничения

- GPU отсутствует, распознавание выполняется на CPU.
- В MVP поддерживается одна камера и один ТВ-экран.
- Штатный сценарий предусматривает строго одно лицо в кадре.
- Биометрические данные и фотографии хранятся локально.
- Самоподписанные сертификаты используются внутри локальной сети.
- Полноценный мониторинг Prometheus/Grafana не входит в MVP; используется `/health`.

## SLA

Целевой SLA: не менее 95% штатных событий должны отображаться на ТВ не позднее 1.2 секунды после появления лица в ROI.
