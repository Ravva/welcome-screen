🔐 Welcome Screen — настройка серверной части

Поддерживается два типа видеоисточников:

  • IP-камера по RTSP — целевой вариант для промышленной эксплуатации.
  • USB-камера или встроенная камера ноутбука — для разработки и тестирования без IP-камеры.

1 Подготовить сервер

Подключиться к серверу по SSH, обновить пакеты, установить базовый набор утилит.

Подключиться
ssh user@SERVER_IP
Обновить пакеты
sudo apt update && sudo apt upgrade -y
Установить базовые утилиты
sudo apt install -y ca-certificates curl gnupg lsb-release git unzip htop nano openssl netcat-openbsd ffmpeg ufw
Проверить версию Ubuntu
lsb_release -a

2 Создать системного пользователя проекта

Опционально. Если будете работать от текущего пользователя — пропустите.

sudo adduser welcome && sudo usermod -aG sudo welcome && su - welcome

3 Установить Docker Engine

Удалить старые версии (если есть)
sudo apt remove -y docker docker-engine docker.io containerd runc
Добавить Docker GPG-ключ
sudo install -m 0755 -d /etc/apt/keyrings && curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg && sudo chmod a+r /etc/apt/keyrings/docker.gpg
Добавить Docker repository
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
Установить Docker Engine
sudo apt update && sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
Проверить версии
docker --version && docker compose version
Добавить пользователя в группу docker
sudo usermod -aG docker $USER && newgrp docker
Проверить запуск без sudo
docker run hello-world

4 Настроить firewall

sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw enable
Проверить статус
sudo ufw status verbose
Порты PostgreSQL, CompreFace и внутренних сервисов наружу открывать не нужно.

5 Клонировать репозиторий

sudo mkdir -p /opt/welcome-screen && sudo chown -R $USER:$USER /opt/welcome-screen
cd /opt && git clone https://github.com/Ravva/welcome-screen.git && cd /opt/welcome-screen
Проверить статус
git status && ls -la

6 Подготовить runtime-директории

mkdir -p docker-data postgres-data compreface-data uploads media snapshots logs certs secrets
chmod 700 secrets && chmod 700 certs
Директория Назначение
postgres-data/данные PostgreSQL
compreface-data/данные CompreFace
uploads/загружаемые фото сотрудников
media/публичные медиа-файлы
snapshots/снимки событий / неизвестных лиц
logs/технические логи
certs/TLS-сертификаты
secrets/локальные секреты

7 Создать .env

nano .env

Пример содержимого:

# Project PROJECT_NAME=welcome-screen APP_ENV=production APP_HOST=welcome-screen.local # Timezone TZ=Asia/Almaty # Backend BACKEND_PORT=3000 JWT_SECRET=change_me_to_long_random_secret ANTI_FLOOD_SECONDS=60 DEFAULT_SIMILARITY_THRESHOLD=0.82 # PostgreSQL POSTGRES_DB=welcome_screen POSTGRES_USER=welcome_user POSTGRES_PASSWORD=change_me_strong_password POSTGRES_PORT=5432 # Camera VIDEO_SOURCE=rtsp # rtsp (IP-камера) или v4l2 (USB/встроенная) CAMERA_NAME=main_entrance CAMERA_RTSP_URL=rtsp://user:password@CAMERA_IP:554/stream1 CAMERA_DEVICE=/dev/video0 # для режима v4l2 # CompreFace COMPREFACE_HOST=compreface COMPREFACE_PORT=8000 COMPREFACE_API_KEY=change_me_after_compreface_setup COMPREFACE_NUM_THREADS=48 # Nginx NGINX_HTTP_PORT=80 NGINX_HTTPS_PORT=443
Сгенерировать JWT-секрет
openssl rand -hex 32
Сгенерировать пароль PostgreSQL
openssl rand -base64 32
Ограничить права на .env
chmod 600 .env
Важно: .env уже исключён из git через .gitignore. Не коммитьте его.

8 Настроить локальное имя сервера

Рекомендуемое имя: welcome-screen.local. Добавить в /etc/hosts:

sudo nano /etc/hosts

Добавить строку:

192.168.1.50 welcome-screen.local
IP-адрес заменить на реальный адрес сервера. Добавить это же имя на рабочих компьютерах администратора и ТВ-устройстве.

9 Создать самоподписанный TLS-сертификат

OpenSSL-config
nano certs/welcome-screen-openssl.cnf

Содержимое:

[req] default_bits = 4096 prompt = no default_md = sha256 distinguished_name = dn x509_extensions = v3_req [dn] C = KZ ST = Local L = Local O = Welcome Screen OU = Internal CN = welcome-screen.local [v3_req] subjectAltName = @alt_names [alt_names] DNS.1 = welcome-screen.local IP.1 = 192.168.1.50
Сгенерировать сертификат
openssl req -x509 -nodes -days 825 -newkey rsa:4096 -keyout certs/welcome-screen.key -out certs/welcome-screen.crt -config certs/welcome-screen-openssl.cnf
chmod 600 certs/welcome-screen.key && chmod 644 certs/welcome-screen.crt
Проверить сертификат
openssl x509 -in certs/welcome-screen.crt -text -noout | grep -E "Subject:|Issuer:|Not Before|Not After|DNS:"

10 Установить сертификат как доверенный

На Ubuntu-клиенте

sudo cp certs/welcome-screen.crt /usr/local/share/ca-certificates/welcome-screen.crt && sudo update-ca-certificates

На Windows-клиенте

Скопировать welcome-screen.crt на Windows-машину, затем:

  1. Открыть mmc
  2. Добавить snap-in Certificates → Computer account
  3. Импортировать сертификат в Trusted Root Certification Authorities

На ТВ-устройстве

Зависит от модели. Практичное решение — использовать мини-ПК / Android box / Chromebox и открыть ТВ-фронтенд в браузере Chrome, где можно импортировать сертификат.

11 Подготовить Nginx-конфигурацию

mkdir -p nginx/conf.d && nano nginx/conf.d/welcome-screen.conf

Содержимое:

server { listen 80; server_name welcome-screen.local; return 301 https://$host$request_uri; } server { listen 443 ssl http2; server_name welcome-screen.local; ssl_certificate /etc/nginx/certs/welcome-screen.crt; ssl_certificate_key /etc/nginx/certs/welcome-screen.key; ssl_protocols TLSv1.2 TLSv1.3; ssl_prefer_server_ciphers off; client_max_body_size 20M; access_log /var/log/nginx/access.log; error_log /var/log/nginx/error.log; location /api/ { proxy_pass http://backend-api:3000/api/; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } location /health { proxy_pass http://backend-api:3000/health; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } location /ws/ { proxy_pass http://backend-api:3000/ws/; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_read_timeout 3600s; proxy_send_timeout 3600s; } location /admin/ { proxy_pass http://admin-frontend:8080/; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } location / { proxy_pass http://tv-frontend:8080/; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }

12 Проверить доступность видеоисточника

Режим RTSP (IP-камера)

ping CAMERA_IP
nc -vz CAMERA_IP 554
ffprobe "rtsp://user:password@CAMERA_IP:554/stream1"
RTSP-path может отличаться в зависимости от модели камеры. Проверьте документацию.

Режим V4L2 (USB / встроенная камера)

Проверить список видеоустройств
ls -la /dev/video*
Проверить параметры камеры
v4l2-ctl --list-devices
v4l2-ctl --device=/dev/video0 --list-formats-ext
Если v4l2-ctl не установлен
sudo apt install -y v4l-utils
Проверить захват тестового кадра
ffmpeg -f v4l2 -i /dev/video0 -frames 1 -y /tmp/test-capture.jpg && ls -la /tmp/test-capture.jpg
Для ноутбука: встроенная камера обычно доступна как /dev/video0. Если используется удалённый сервер без монитора, USB-камера должна быть физически подключена и определена ядром.

13 CompreFace

Будет развёрнут как часть Docker-контура проекта. Основные требования:

  • backend и Stream Handler видят CompreFace по внутреннему DNS Docker-сети
  • порты CompreFace не публикуются наружу
  • API-ключ хранится в .env
  • данные сохраняются в compreface-data/
  • NUM_THREADS выставляется в 48–52 через .env
  • если используется USB-камера — Stream Handler получает видеопоток через V4L2 вместо RTSP

15 Запуск и диагностика

После добавления docker-compose.yml в репозиторий:

cd /opt/welcome-screen && git pull
docker compose up -d
Проверить контейнеры
docker compose ps
Посмотреть логи всех сервисов
docker compose logs -f
Логи конкретного сервиса
docker compose logs -f backend-api
Проверить /health
curl -k https://welcome-screen.local/health
Ожидаемый ответ /health: 
{
  "status": "ok",
  "version": "1.0.0",
  "services": {
    "postgres": "ok",
    "compreface": "ok",
    "streamHandler": "ok",
    "rtspCamera": "ok",
    "websocket": "ok",
    "storage": "ok"
  }
}

16 Эксплуатация

Обновить проект и перезапустить

cd /opt/welcome-screen && git pull && docker compose pull && docker compose up -d --build

Перезапустить сервисы

docker compose restart

Остановить

docker compose down

Мониторинг ресурсов

docker stats
htop

Резервное копирование

cd /opt && tar -czf welcome-screen-backup-$(date +%F).tar.gz welcome-screen/.env welcome-screen/certs welcome-screen/nginx welcome-screen/postgres-data welcome-screen/compreface-data welcome-screen/uploads welcome-screen/media welcome-screen/snapshots
Backup хранить вне основного сервера.
